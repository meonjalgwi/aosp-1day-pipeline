# 14주차 로드맵

프로젝트 "aosp-1day-pipeline (먼잘귀)"의 주차별 목표와 담당자입니다.

- 담당자 표기: 나연 = @zv9uvr, 현아 = @gusdkcjs4, 서진 = @seojinn0713
- 1~6주차(설계·프로토타입 단계)는 각자 자기 Agent를 병렬로 설계·구현하며 서로 PR 리뷰
- 7~14주차(통합·구현 단계, 마지막 2개월)는 나연이 전체 파이프라인 통합 구현을 전담

## 1단계: 설계·프로토타입 (1~6주차)

| 주차 | 목표 | 담당 | 산출물 |
| --- | --- | --- | --- |
| 1주 | 범위 확정 | 전원 | Android 보안구조/App Sandbox/Binder/Framework 개요 학습, "공개 패치가 있는 Framework 취약점" 선정 기준 수립, 후보 CVE 8~10개 목록 |
| 2주 | 실험 환경 구축 | 전원 | Android Studio/SDK/ADB/Emulator 구축, 패치 전·후 환경 초기화 스크립트, 테스트 APK 배포·로그 수집 |
| 3주 | 수동 재현 기준선 | 전원 | 가장 쉬운 CVE 1개를 직접 분석해 수정 전후 코드·호출 경로·발생 조건·재현 절차·성공 판정 로그를 정답 데이터로 작성 |
| 4주 | Collector Agent | 나연 | CVE 번호로부터 보안 공지·영향 버전·컴포넌트·패치 커밋을 구조화된 JSON으로 저장, 잘못된 링크/비공개 버그 처리 |
| 5주 | Patch Analyst Agent | 현아 | 변경된 파일·메서드 추출, 조건문·권한 검사·입력 검증 변경 요약 및 취약점 가설 생성, 사람이 만든 정답과 비교 |
| 6주 | Harness Agent | 서진 | APK/instrumentation 테스트 템플릿 구축, 입력값·Intent·Binder 호출을 템플릿 안에서 조합 |

4~6주는 원칙적으로 병렬 진행합니다. 각자 자기 Agent를 설계하면서 매주 다른 두 사람의 PR을 리뷰합니다.

## 2단계: 통합·구현 (7~14주차, 마지막 2개월)

| 주차 | 목표 | 담당 | 산출물 |
| --- | --- | --- | --- |
| 7주 | 실행 자동화 | 나연 | Emulator 스냅샷 복원 → APK 설치 → 테스트 실행 → logcat/예외/상태 수집 → 초기화까지 한 명령으로 실행 |
| 8주 | 검증·보고서 Agent | 나연 | 패치 전후 차이 자동 판정, Agent 설명이 로그·diff에 근거하는지 검사, HTML/Markdown 보고서 생성 |
| 9주 | 복수 CVE 통합 | 나연 | CVE 2·3 적용, 한 취약점에 과적합된 규칙 분리, 실패 원인을 환경/빌드/가설/테스트 실패로 분류 |
| 10주 | 정규학기 MVP | 나연 (구현) + 전원 (발표) | CVE 입력~최종 보고서 end-to-end 데모, 수동 분석/단순 LLM/Tool-using Agent 3가지 기준선 비교 |
| 11주(집중기) | 반복성 향상 | 나연 | 동일 실험 반복 실행 성공률 측정, Emulator 부팅 지연·서비스 초기화·flaky test 재시도 정책 |
| 12주(집중기) | 일반화 실험 | 나연 | 보지 않은 CVE 1~2개 적용, 패치 함수 Top-k 정확도·재현 성공률 측정, 실패 사례 분석 |
| 13주(집중기) | 결과물 완성 | 나연 (구현) + 전원 (문서화) | 데모 UI/CLI 정리, 실험 환경 자동 설치, 데이터 스키마, Agent prompt/tool contract 문서화 |
| 14주(집중기) | 최종 평가 | 전원 | 최종 실험표, 발표, 논문형 보고서, 위험 입력·실제 exploit 제거한 재현 데이터셋 공개 준비 |

## 협업 규칙

1. 매 주차 시작 전 GitHub Issue를 만들고 담당자를 배정합니다.
2. 이슈별로 브랜치를 만들어 작업합니다.
3. 작업 완료 후 PR을 생성하고, 팀원 최소 1명의 리뷰 승인을 받은 뒤 merge합니다.
4. PR 본문에 `Closes #이슈번호`로 관련 이슈를 연결합니다.
